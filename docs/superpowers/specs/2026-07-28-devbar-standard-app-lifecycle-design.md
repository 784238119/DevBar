# DevBar 普通应用与菜单栏协同设计

**日期：** 2026-07-28  
**状态：** 已确认，待实施

## 1. 背景

DevBar 当前被实现为仅菜单栏应用：

- `Configuration/DevBar-Info.plist` 设置了 `LSUIElement=true`，因此应用不显示在 Dock。
- 生产入口只有 `MenuBarExtra`、系统设置场景和日志窗口，没有正式主窗口。
- 用户从 Finder 或构建目录打开应用后，只能从菜单栏判断应用是否启动。

这与“像普通 macOS 软件一样从 Dock 打开，同时在菜单栏执行运行状态查看和快捷操作”的目标不一致。

## 2. 目标

DevBar 调整为普通 macOS 应用与菜单栏工具并存的混合模式：

1. 应用运行时在 Dock 显示 DevBar 图标。
2. 正常启动时自动显示一个标题为“DevBar”的主窗口。
3. 用户关闭主窗口后，应用继续运行，菜单栏状态与快捷操作保持可用。
4. 用户再次点击 Dock 图标时，重新显示并激活主窗口。
5. 菜单栏继续提供工作区状态、单服务启停、整组启停、日志和配置入口。
6. 退出应用继续使用现有安全退出流程；存在运行中服务时，必须确认并完成停服后退出。

## 3. 非目标

本次不包含以下内容：

- 不重新设计工作区、服务配置和偏好设置界面。
- 不新增独立运行仪表盘。
- 不改变服务启动、停止、健康检查、日志或配置持久化协议。
- 不移除 `MenuBarExtra`，也不减少现有菜单栏能力。
- 不增加开机自启、登录启动或服务自动启动。
- 不改变应用退出时的进程回收和失败保护策略。

## 4. 用户可见行为

### 4.1 正常启动

- 从 Finder、Dock、Spotlight、终端或 Xcode 启动 DevBar 时，应用显示 Dock 图标并成为前台应用。
- 应用创建并显示唯一的主窗口。
- 主窗口复用现有工作区与服务管理内容，避免产生第二套配置状态或保存路径。
- 首次启动与已有配置场景都进入同一主窗口；首次启动不再额外打开一个重复的系统设置窗口。

### 4.2 关闭和重新打开

- 点击主窗口关闭按钮只关闭窗口，不终止应用，也不停止服务。
- 菜单栏图标继续显示聚合运行状态，所有快捷操作继续工作。
- 当主窗口不存在或不可见时，点击 Dock 图标重新创建或显示该窗口，并将其置于前台。
- 当主窗口已经可见时，点击 Dock 图标只激活并前置现有窗口，不创建重复窗口。

### 4.3 菜单栏与窗口协同

- 菜单栏中的配置入口打开或前置同一个主窗口。
- 日志入口继续打开独立的“服务日志”窗口。
- 多次触发主窗口或日志窗口入口不得产生语义重复的窗口实例。
- 主窗口与菜单栏共享同一个 `AppDependencies` 和 `AppState`，状态变化应即时一致。

### 4.4 退出

- `⌘Q`、应用菜单的退出项和菜单栏“退出 DevBar”执行同一退出流程。
- 关闭最后一个窗口不等于退出。
- 如果仍有服务运行，继续使用 `QuitCoordinator` 显示确认并按现有信号升级策略停止服务。
- 停服失败时取消退出，应用与菜单栏继续运行。

## 5. 技术设计

### 5.1 应用激活策略

- 从 Info.plist 移除 `LSUIElement=true`，恢复普通应用的 Dock 和应用切换器行为。
- 不在运行时反复切换 `NSApplication.ActivationPolicy`，避免 Dock 图标闪烁和激活状态不一致。

### 5.2 场景结构

生产 `App` 保留：

- 一个固定标识的主窗口场景，标题为“DevBar”；
- 现有 `MenuBarExtra`；
- 独立的“服务日志”窗口。

主窗口内容复用现有 `SettingsSceneContent`、`SettingsViewModel` 与 `SettingsRootView`。移除独立的 SwiftUI `Settings` 场景，替换标准应用菜单中的“设置…”命令，使 `⌘,` 调用主窗口打开动作。应用中不存在第二个配置窗口。

### 5.3 窗口协调

使用一个窄职责的主窗口打开动作统一处理以下入口：

- 应用首次启动；
- Dock 重新激活；
- 菜单栏配置按钮；
- 标准应用菜单中的配置入口。

窗口协调器只维护主窗口的显示/前置能力，不持有业务状态。SwiftUI 主窗口场景向协调器注册可测试的打开动作；窗口视图向协调器报告当前窗口实例。菜单命令、菜单栏入口和应用委托都调用该协调器，不通过窗口标题或当前最前窗口猜测目标。

`DevBarApplicationDelegate.applicationShouldHandleReopen` 负责 Dock 重开语义：没有可见主窗口时调用已注册的打开动作；已有主窗口时激活并前置。窗口协调不创建新的 `AppState` 或 `SettingsViewModel` 数据源。

### 5.4 生命周期

- 应用启动完成后请求显示主窗口，并调用 `NSApp.activate(ignoringOtherApps: true)`。
- 主窗口关闭时不调用 `terminate`。
- `applicationShouldTerminateAfterLastWindowClosed` 明确返回 `false`，防止未来场景调整破坏菜单栏驻留行为。
- 现有 `applicationShouldTerminate` 保持为唯一安全退出关口。

## 6. 异常与边界

- 配置仍在异步加载时，主窗口显示现有加载状态；不得同时打开另一个配置窗口。
- 配置损坏或 Shell 环境不可用时，主窗口继续承载现有恢复提示，不因窗口生命周期调整而绕过校验。
- 用户快速连续点击 Dock 或菜单栏配置入口时，只允许前置同一窗口。
- 日志窗口关闭不影响主窗口和菜单栏；主窗口关闭不影响日志窗口。
- 应用被强制退出不保证安全停服，这仍属于系统强制退出的既有风险，不在本次改变。
- UI 测试的 `--ui-testing` 隔离模式不得读取或写入真实用户配置，也不得因生产窗口调整失去确定性。

## 7. 测试与验收

### 7.1 自动化测试

- 验证生产 Info.plist 不再声明 `LSUIElement=true`。
- 验证关闭最后一个窗口不会请求终止应用。
- 验证 Dock 重开请求会打开或前置主窗口。
- 验证重复重开请求不会创建多个主窗口。
- 更新 UI 测试，使正常测试宿主能够验证主窗口的工作区内容和配置入口。
- 回归现有菜单栏、配置、日志和安全退出测试。

### 7.2 手工验收

1. 构建并从 Finder 打开 `DevBar.app`，确认 Dock 出现正确应用图标且主窗口自动显示。
2. 关闭主窗口，确认 Dock 与菜单栏图标仍存在。
3. 点击 Dock 图标，确认原主窗口重新显示并置前，且没有重复窗口。
4. 从菜单栏启动一个测试服务，确认主窗口关闭后状态仍更新、快捷启停仍可用。
5. 从菜单栏打开主窗口和日志窗口，确认入口不会产生重复窗口。
6. 在服务运行时按 `⌘Q`，确认出现安全退出提示；取消后应用继续运行。
7. 再次退出并完成停服，确认应用、Dock 图标和菜单栏图标全部消失，且没有残留受管进程。

## 8. 完成标准

只有同时满足以下条件才算完成：

- DevBar 具备普通应用的 Dock、前台激活和主窗口体验。
- 关闭主窗口后仍能作为菜单栏工具稳定运行。
- Dock、菜单栏和应用菜单始终打开同一个主窗口。
- 现有服务控制、日志、配置持久化和安全退出行为无回归。
- 自动化测试通过，并完成上述手工生命周期验收。
