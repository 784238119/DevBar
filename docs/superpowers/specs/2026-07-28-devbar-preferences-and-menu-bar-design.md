# DevBar 偏好设置布局、菜单栏开关与服务编辑稳定性设计

**日期：** 2026-07-28  
**状态：** 方案 A 已确认，书面规格待用户复核

## 1. 背景与问题

当前主窗口同时承载工作区配置和全局偏好设置。进入偏好设置后，左侧仍固定保留 220 pt 的工作区侧栏；当没有工作区时，该区域几乎完全空白，偏好设置只能使用剩余宽度。

另外存在两个独立问题：

- 菜单栏图标无法由用户关闭，且当前中性图标 `terminal` 容易与终端类应用混淆。
- 服务编辑 Sheet 的字段 Binding 会从可空的 `serviceEditor` 强制取值。Sheet 关闭或状态切换期间，SwiftUI 仍可能短暂读取 Binding，从而触发 `preconditionFailure` 并直接终止应用。

## 2. 目标

1. 偏好设置使用整个主窗口内容区，不显示工作区侧栏。
2. 用户可在偏好设置中即时控制菜单栏图标是否显示。
3. 菜单栏显示偏好跨应用重启保持，默认开启。
4. 隐藏菜单栏图标后，仍可通过 Dock、主窗口和标准应用菜单恢复。
5. 菜单栏中性状态图标从终端语义改为开发工具语义。
6. 编辑或关闭服务配置时，不得因为短暂的展示状态变化导致应用退出。

## 3. 非目标

- 不改变工作区、服务、日志和 Shell 偏好的配置格式。
- 不增加应用登录自启或服务自动启动。
- 不改变“加入启动全部”的业务含义。
- 不重新设计工作区页面、菜单栏面板或日志窗口。
- 不移除 Dock 图标，也不把 DevBar 改回仅菜单栏应用。
- 不让“显示菜单栏图标”受主窗口底部“保存/取消”控制。

## 4. 用户可见行为

### 4.1 偏好设置整页布局

- 选择“偏好设置”后，主窗口只显示偏好设置内容和统一底部操作栏。
- 截图中固定的工作区侧栏和分隔线不渲染，偏好设置使用整个 980 pt 窗口宽度。
- 偏好设置页顶部提供工作区入口：
  - 已有工作区时显示“返回工作区”，进入最近一次可用工作区。
  - 没有工作区时显示“添加工作区”，继续使用现有目录选择流程。
- 工作区配置页面仍保留现有侧栏，用于工作区选择、排序、新增和进入偏好设置。

### 4.2 菜单栏显示开关

- 偏好设置新增复选框“显示菜单栏图标”。
- 默认值为开启。
- 用户切换后立即插入或移除 `MenuBarExtra`，不需要点击主窗口底部“保存”。
- 该偏好独立存储在 `UserDefaults`，避免因工作区配置校验或保存失败而回滚应用外观状态。
- 关闭菜单栏图标时，Dock 图标、主窗口、`⌘,` 和应用菜单仍然可用。
- 重新开启后，菜单栏图标和现有菜单栏面板恢复，业务状态沿用共享的 `AppState`，不得创建第二份状态。

### 4.3 菜单栏图标

- 中性状态图标由 `terminal` 改为 `hammer`。
- 启动中或停止中的工作状态使用 `hammer.fill`。
- 就绪和错误状态继续使用现有的 `checkmark.circle.fill` 与 `exclamationmark.triangle.fill`，保留清晰的状态语义。
- 无障碍标签继续为“DevBar”。

### 4.4 服务编辑器

- 打开“添加服务”或“编辑服务”时，Sheet 创建自己的本地 `ServiceConfig` 草稿。
- 文本输入、目录、环境变量、是否加入启动全部和健康检查只修改本地草稿。
- 点击“保存服务”时通过明确的 ViewModel 方法一次性提交草稿，然后清空展示状态并关闭 Sheet。
- 点击“取消”、关闭按钮或系统关闭 Sheet 时丢弃本地草稿并清空展示状态。
- Sheet 不再从可空的 `serviceEditor` 创建会崩溃的长期 Binding，也不使用默认值掩盖失效状态。

## 5. 技术设计

### 5.1 设置根布局

`SettingsRootView` 根据 `viewModel.showsPreferences` 选择两个互斥布局：

- 偏好设置：`PreferencesView + footer`，不创建 sidebar 或 Divider。
- 工作区配置：现有 `sidebar + Divider + workspace content + footer`。

底部保存、取消、检查配置和通知区域继续复用同一个实现，不复制保存逻辑。

`SettingsViewModel` 记录最近一次选中的工作区 ID。进入偏好设置不销毁该选择；从偏好设置返回时优先恢复它，如果它已被删除则选择第一个现存工作区。无工作区时由偏好设置页调用现有 `addWorkspace()`。

### 5.2 菜单栏可见性

新增一个窄职责的可观察偏好对象，封装 `UserDefaults` 键和默认值。生产 `App` 与 `PreferencesView` 共享同一实例：

- `ProductionDevBarApp` 把其 Binding 传给 `MenuBarExtra(isInserted:)`。
- `SettingsSceneContent` 将实例传入 `SettingsRootView` 和 `PreferencesView`。
- UI 测试使用内存实现或隔离的测试 defaults，不能修改真实用户偏好。

持久化键是应用界面偏好，不加入 schema version 1 的 `AppConfig`，避免把即时菜单栏行为错误地绑定到配置文件的草稿保存周期。

### 5.3 服务编辑草稿

`ServiceEditorDraft` 继续负责标识“新增或编辑哪个服务”，但 Sheet 的可编辑字段由本地 `@State` 持有。ViewModel 提供两个明确边界：

- 提交给指定工作区的服务草稿；
- 结束编辑并清空展示状态。

`.sheet(item:)` 的 `onDismiss` 也调用结束编辑，覆盖 Esc、系统关闭和程序化关闭。提交方法必须校验工作区和目标服务仍存在；目标在编辑期间被删除时不追加错误服务，并向设置页发布失败通知。

## 6. 风险与边界

- `MenuBarExtra(isInserted:)` 需要稳定的 Binding；不能在 View 重绘时重新创建偏好对象。
- 隐藏菜单栏图标不得调用退出、停服或重建 `AppState`。
- 菜单栏关闭期间服务仍可能运行；Dock 与主窗口必须保持，退出继续走 `QuitCoordinator`。
- 偏好设置整页布局不能丢失“添加工作区”入口。
- “显示菜单栏图标”即时生效，不应被底部“取消”撤销；界面文案需避免把它误解为普通配置草稿。
- 服务编辑器不得用空服务作为 Binding 回退值，否则可能把用户输入静默保存到错误对象。
- 编辑期间目标服务或工作区被删除属于异常状态，必须安全失败，不得崩溃或错误追加。

## 7. 测试与验收

### 7.1 自动化测试

- 无工作区时进入偏好设置，不显示 `settings.sidebar`，仍能触发添加工作区。
- 有工作区时进入偏好设置不显示侧栏，返回后恢复工作区页面和侧栏。
- 菜单栏显示偏好默认开启、切换后立即更新、重新创建偏好对象后保持。
- 菜单栏关闭不影响主窗口协调器和应用驻留行为。
- 中性和工作状态分别映射到 `hammer`、`hammer.fill`。
- 服务编辑本地草稿在取消时不改原配置，在保存时只提交一次。
- Sheet 状态在输入、取消或外部关闭期间失效时不触发崩溃。
- 回归现有配置校验、配置保存、菜单栏操作和退出测试。

### 7.2 手工验收

1. 没有工作区时打开偏好设置，确认左侧空白栏消失，偏好设置占满主窗口。
2. 点击“添加工作区”，确认仍能选择目录并进入工作区配置。
3. 有工作区时进入偏好设置，确认仍为整页；点击“返回工作区”恢复侧栏和原选择。
4. 取消勾选“显示菜单栏图标”，确认图标立即消失，Dock 和主窗口仍存在。
5. 通过主窗口重新勾选，确认菜单栏图标和面板恢复；重启应用后设置保持。
6. 确认菜单栏停止状态显示 `hammer`，工作状态显示 `hammer.fill`。
7. 连续编辑启动命令、取消、重新打开并保存，确认应用不退出且取消不污染配置。
8. 有服务运行时隐藏菜单栏图标，再通过 `⌘Q` 退出，确认安全停服流程仍生效。
